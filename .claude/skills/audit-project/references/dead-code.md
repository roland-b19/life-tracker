# Dead-code tools

Read this when a project wants a dead-code tool, or in a milestone audit of a project that has one.

- **Optional, per project.** A project sets its tool up only if it wants one; installing it follows find-or-build-tool's limits (free, vetted).
- **Milestone audits only.** audit-project runs it when a feature or roadmap stage is finished. Never put it in the one check command: these tools report code that is reached only through reflection, string lookups, config, generated code or a public API, so a false hit would block every change.
- **Every hit is judged before removal.** A hit is a suspect, not proof: search every kind of reference, as audit-project's "Prove unused" step says, before it goes on the remove list. Anything you can't prove unused goes on the ask list.
- **Mark a confirmed false positive in the tool's own config**, with a comment saying why, so the next audit doesn't report it again. Prefer the config file to inline comments.

| Stack | Tool (license) | Install | Run | Common false positives | Mark a false positive |
|---|---|---|---|---|---|
| JavaScript, TypeScript | knip (ISC) | `npm init @knip/config` | `npx knip` | entry files it can't find (scripts, HTML `<script src>`, generated files), computed dynamic imports, path aliases, a framework without a knip plugin, a library's public API | `entry` and `project` in `knip.json`; JSDoc `@public`; the `ignore*` options as a last resort |
| Python | vulture (MIT) | `pip install vulture` | `vulture <src folder> whitelist.py` | code called implicitly: framework hooks, decorators, `visit_*` methods, attributes read by name | a whitelist file (`vulture <src folder> --make-whitelist > whitelist.py`, then trim it to the false positives); `--ignore-decorators "@app.route"` |
| Go | deadcode (BSD-3-Clause) | `go install golang.org/x/tools/cmd/deadcode@latest` | `deadcode ./...`; a library: `deadcode -test ./...` (it starts from `main`, so without `-test` most of a library looks dead) | functions reached only through `//go:linkname` or assembly, code used only under other build tags or GOOS/GOARCH (run once per configuration), methods needed to satisfy an interface | no ignore annotation: `-filter=<regex>` limits the packages reported; `-whylive=<func>` explains why a function is kept |
| Swift | SwiftLint analyzer rule `unused_declaration` (MIT) | `brew install swiftlint`; list `unused_declaration` under `analyzer_rules:` in `.swiftlint.yml` (opt-in) | clean the build folder, `xcodebuild -workspace <w>.xcworkspace -scheme <s> > xcodebuild.log`, then `swiftlint analyze --compiler-log-path xcodebuild.log` (needs a clean build's log; slow) | Objective-C and other dynamic calls, `#if` branches not built, members used only by Interface Builder | `// swiftlint:disable:next unused_declaration`; the rule's `related_usrs_to_skip` option |
| Rust | the compiler's `dead_code` lint (built in) and cargo-machete (MIT) for dependencies | `cargo install cargo-machete` | `cargo check` (reports `dead_code`); `cargo machete` (exit 1 = unused dependencies) | `dead_code` skips `pub` items of a library and flags fields kept only for their drop side effects; cargo-machete flags crates used only in `build.rs`-generated code or imported under another name | `#[expect(dead_code, reason = "...")]` (warns once the code is used); `[package.metadata.cargo-machete] ignored = ["<crate>"]` |
| Kotlin | detekt (Apache-2.0), stable 1.23 | Gradle plugin `id("io.gitlab.arturbosch.detekt") version "1.23.8"` | `./gradlew detekt`; `./gradlew detektMain` for the rules that need type resolution | members called by frameworks through reflection or annotations | the rule's `allowedNames` in `detekt.yml`; `@Suppress("UnusedPrivateMember")`; a baseline (`./gradlew detektBaseline`) |
| Java | PMD (BSD-style) | download the release zip from GitHub and put its `bin/` on the PATH | `pmd check -d src/main/java -f text -R unused.xml`, where `unused.xml` is a ruleset that references `category/java/bestpractices.xml/` `UnusedPrivateField`, `UnusedPrivateMethod`, `UnusedLocalVariable`, `UnusedFormalParameter` and `UnusedAssignment` | fields set by frameworks through reflection (annotated fields are skipped by default) | the rule's `ignoredAnnotations` property; `@SuppressWarnings("PMD.<RuleName>")` |
| C# | the .NET SDK's code-style analyzers (free, built in) | `<EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>` in the project file, and in `.editorconfig` under `[*.cs]`: `dotnet_diagnostic.IDE0051.severity = warning`, the same for `IDE0052` and `IDE0060` | `dotnet build` (they are off in command-line builds without the two settings) | parameters a signature needs (delegates, members a framework calls) | name the parameter `_`; `#pragma warning disable IDE0051` with a reason |

Notes, checked against each tool's docs on 2026-11-17:
- Periphery, the usual Swift tool, became a commercial product in August 2026 (its open-source repo is archived), so it is not the default.
- detekt's site shows the 2.0 alphas by default, which rename the plugin (`dev.detekt`) and some rules (`UnusedPrivateMember` becomes `UnusedPrivateFunction`). Use the names of the version the project runs.
