Interface design rules

A project-agnostic rule set for calm, orderly app interfaces in light and dark mode: principles, color roles, contrast, type, spacing, every component in every state, motion, accessibility, and the decisions behind them with the options that were rejected. Every example is drawn live in both modes. Start a new project from here, swap the accent, and keep the rules.

How to use these rules

  • U1Every rule has an ID (P2, B3, H1…). Quote it in a request or a review: "this breaks K5".
  • U2Every example is drawn twice, light on the left and dark on the right (stacked on a phone). States that need an action (hover, focus) are also shown frozen.
  • U3The rules are general; the values are a starting point. A project keeps the rules, swaps the accent (Choosing the accent), and may tune sizes, as long as it tunes them in one place.
  • U4Each project then keeps its own design-system page (its tokens, its components, its decisions) built from this one. In a project, its CSS wins: when the page and the CSS differ, fix the page in the same change.

Principles

The target feel: serious, motivating, energetic and orderly, like a good native app that people open many times a day.

  • P1Change the look, not the structure. Visual work never moves screens, adds features or changes layouts unless that change is asked for on its own.
  • P2One accent color, used only for "act" and "progress": the primary button, progress fills and rings, the active segment's dot, the focus ring, a checked checkbox, a selected chip. Never decoration, never headings.
  • P3Accent and status colors are never text. Text is one of two tokens: --text or --secondary. A colored fill carries a dark --on-tint label.
  • P4A status is never color alone. A word always goes with it: a badge's label, an "Over" note.
  • P5Raised means you can act on it. Buttons, fields, selects, chips, fold arrows, tabs: a hairline edge and a soft shadow. Tags, counts and info tiles stay flat. Containers (cards, dialogs) keep the card look.
  • P6Neutral grey for everything that is not the primary action. Secondary, small, icon and toast buttons share one grey fill. Selected neutral things use a neutral wash, never the solid accent.
  • P7Two modes, one token list. Light and dark follow the system or a manual Auto / Light / Dark switch; every color token is written once with light-dark(light, dark).
  • P8"Alive" without animation. Big bold numerals for key numbers, a clear weight hierarchy, glass cards on a soft accent glow. Motion is rare and listed (Motion).
  • P9One font family. Hierarchy comes from size and weight. Numbers that line up use tabular figures.
  • P10One way to do each thing. A style is set once on the shared structure (tokens, base element rules, shared classes) and inherited; no per-page copies. One page is the reference and every other page matches it.
  • P11No literal colors outside the token block. Everything else is a token or a color-mix() of tokens. A test enforces it.
  • P12Every change can be undone. A toast with Undo follows every change (a delete, an edit, a setting), instead of "Are you sure?" dialogs.

Color tokens

All tokens live in one :root block with color-scheme: light dark. [data-theme="light"] or [data-theme="dark"] on <html> forces a mode (the manual switch, saved per device and applied by a tiny inline script before the first paint, so there is no flash). Every token that differs between modes is registered with @property … { syntax: "<color>" } so the mode change can fade.

  • C1Use a token by its role, not its look: a field is --surface-secondary because it is a control, not because it is "the light grey".
  • C2Accent and status colors have about the same brightness within a mode: no pale colors in dark, no dull or brownish ones in light.
  • C3A new color is a new token with both values, registered and added to the fade list; never a literal in a rule.
  • C4Neutrals are a cool slate, not pure grey or pure black: they give depth in both modes and let one saturated accent carry all the meaning.

Choosing the accent

  • AC1Swap these together, never one alone: --tint, --tint-hover, --tint-subtle, --glow (and --on-tint if the new accent is dark).
  • AC2Pick a mid-bright, saturated hue: a dark label (--on-tint, a very dark shade of the accent's own hue) on it must reach 4.5:1, and the fill on the card and the page must reach 3:1 (K2, K3).
  • AC3The dark-mode value is a little brighter than the light one; --tint-hover is one step brighter again in each mode.
  • AC4--tint-subtle is the accent at 16% alpha in light and 18% in dark; --glow at about 26% and 30%.
  • AC5The accent must differ clearly from --success, --warning and --danger. A green accent makes success ambiguous: then move success toward a classic green and keep words on every status (P4).
  • AC6One accent for the whole app. Per-page or per-section accents were tried and rejected: the color stops meaning "act".

Contrast and color use

  • K1Text at least 4.5:1 in both modes: --text and --secondary on every surface (page, page under the glow's peak, card, control fill, solid, dialog) and on the -subtle fills.
  • K2--on-tint (dark, the same in both modes) on --tint, --tint-hover, --success and --warning: at least 4.5:1. Check it on --danger before using it there; usually it fails, so a danger fill is subtle with --text (B7).
  • K3Colored fills (accent, status) at least 3:1 against the card and the page. A deliberate exception (say a golden warning at 2.9:1) is written down, with the status word carrying the meaning, and the test pins its floor.
  • K4No saturated fill on the grey control fill (it drops under 3:1 in light): a track is --separator or a -subtle fill.
  • K5No color: declaration takes the accent or a status color (fills, borders, SVG fill and stroke may). Links are --text, weight 600. Error text is --text, small, never red.
  • K6The only allowed accent "text" is a decorative unit beside a big display numeral (large text needs 3:1, which the fill rule already guarantees), and only when it carries no meaning on its own.

Typography

  • T1One family everywhere; base 1.0625rem, line-height 1.5, antialiased. The starter uses a system monospace stack (ui-monospace, "SF Mono", Menlo, Consolas, monospace) for an even rhythm and aligned numbers; a sans family works the same way.
  • T2Headings: line-height 1.2, letter-spacing -0.015em, text-wrap: balance.
  • T3Hierarchy by weight and size, not color: 800 titles and numerals; 700 buttons and caps labels; 600 row titles and small buttons; 500 navigation and messages; 400 body.
  • T4Numbers that line up (lists, totals, timers, charts) use font-variant-numeric: tabular-nums.
  • T5On touch devices fields use at least 16px, so iOS does not zoom on focus.

Key numerals

  • N1The one or two numbers a screen exists for are big: clamp(2rem, 9vw, 2.7rem), 800, -0.03em, tabular. Every number of the same kind on a screen gets the same size (don't make only one of four tiles big). A unit or "of N" beside it stays small.
  • N2A big numeral and the line under it are trimmed to their letters (text-box: trim-both cap alphabetic), so the margins around them are the gaps you see.
  • N3A numeral may count up to its new value (ease-out, about 600ms); with reduced motion it jumps.

Page layout

  • L1Background: --background plus two soft accent glow patches (radial-gradient(75% 70% at 0% 0%, var(--glow), transparent) and the same at 100% 100%), one hue, drawn by fixed pseudo-elements 100lvh tall so every page has the same backdrop while it scrolls. Avoid background-attachment: fixed (broken on iOS).
  • L2On a centred screen that never scrolls (sign-in, not found, error) the glow is position: absolute: iOS Safari draws nothing fixed under its bottom bar.
  • L3Content width: min(100% - 1.5rem, 82rem), wider gutters from 640px (2.5rem) and 1024px (4rem). Two-column grids from about 992px (1.6fr 1fr), gap 1.25–1.5rem between cards.
  • L4Phone: a bottom tab bar, fixed 0.75rem from the sides and 0.5rem plus the safe area from the bottom; the toast sits above it. Desktop (≥1024px): a 248px sidebar, the toast bottom right.
The page: background + glow from the top left and bottom right

Spacing inside a card

  • S1Card padding --card-pad: 1.35rem (1.6rem from 768px).
  • S2Title → content: 1rem visible. Block → block: 1rem. Group → group: 1rem. A group label sits 0.25rem above its rows.
  • S3The last line of a card sits exactly one card padding from the bottom edge: the last element drops its bottom margin.
  • S4List rows carry 0.5rem padding top and bottom; the header before a list keeps 0.5rem and the list 0.5rem, so the gap reads as 1rem.
  • S5A card's sub line sits 0.5rem under its title. A card header wraps, gap 1rem 0.75rem.
  • S6Forms: fields 1rem apart; the action buttons share the row equally (flex 1, gap 0.75rem). Fix spacing with these shared rules, never with per-card tweaks.

Surfaces, raised and flat

  • E1Surface steps, back to front: page --background → glass card --surface (60% alpha over the glow) → control fill --surface-secondary → --surface-solid (tab bar, menu, segmented thumb) → --surface-modal (dialog, toast).
  • E2The raised recipe is border: 1px solid var(--card-edge); box-shadow: var(--card-shadow) (a 1px near shadow plus a soft far one). It goes on cards, bars, menus, dialogs, toasts, segmented tracks, every filled button, every field and select, the active nav link, group boxes and fold arrows.
  • E3Flat (no edge, no shadow): badges and tags, counts, stat tiles, the chat log, and clear controls that sit on a track (tab items, segments).
  • E4Blur only where content passes under: the sidebar and the scrims (dialog 20px, menu 8px). Cards carry no blur (it costs paint and adds nothing on a still page).

Buttons

  • B1Primary: --tint fill, --on-tint label, 700, -0.01em, padding 0.65rem 1.25rem, min-height 2.75rem, radius 0.85rem, raised. Hover --tint-hover. One primary per view.
  • B2Its edge is color-mix(in srgb, var(--tint), var(--text) 35%): the plain hairline vanishes on a saturated fill.
  • B3A primary that waits for its fields (Save, Send, Add) looks like a grey secondary button while disabled: the grey fill, the plain hairline, still raised, opacity 1, label color-mix(in srgb, var(--text) 45%, transparent). It reads as "a button you can't press yet", then turns accent once the fields are valid.
  • B4A primary that is busy (signing in, sending) keeps its accent look with cursor: progress: busy is not "unavailable".
  • B5Any other disabled button: opacity 0.45, cursor: not-allowed.
  • B6Secondary: --text on --surface-secondary. Small: the same fill, min-height 2.25rem, 0.875rem/600, radius 0.7rem, a 44px hit area from a pseudo-element. Hover both: color-mix(--surface-secondary, --text 8%). Never accent.
  • B7Destructive: --text on --danger-subtle, hover 8% toward the text. A faint red fill, never a red label or a solid red button; Undo (P12) is the safety net.
  • B8Icon button (row Edit / Delete): 44×44, the grey fill, radius 0.85rem, an aria-label; disabled opacity 0.35.
  • B9A small button on a grey box takes --surface-solid so it stands out from the box.
  • B10Clear controls (tab items, segments, a whole-row select) have no fill and no shadow.
  • B11Pressing changes nothing: no scale, no pulse, no press color.

Hover, focus and press

  • Y1Hover exists only inside @media (hover: hover), so a phone never keeps a stuck hover.
  • Y2One hover step per family: accent → --tint-hover; neutral fills → 8% toward --text; destructive → 8% toward --text; fields → 5%; idle tabs and segments → the --highlight wash with --text; idle nav links → the grey fill with --text; round close buttons also turn their icon to --text.
  • Y3Focus: buttons and checkboxes get a 2px --tint outline, offset 2px, on :focus-visible. Fields show no ring: their fill steps to 8% (one step past hover).
  • Y4Rows have no hover highlight. Press has no effect (B11).

Fields and selects

  • F1Input, select, textarea: min-height 2.75rem, padding 0.65rem 0.95rem, --surface-secondary, raised (fields are actionable), radius 0.85rem. Placeholder --secondary.
  • F2A label sits above its field, gap 0.35rem, 600, 0.9rem.
  • F3The select's chevron is drawn with two linear-gradient strokes in --secondary (no data-URI), so it follows the token in both modes.
  • F4Time and date inputs use appearance: none and min-width: 0, so they never overflow on iOS.
  • F5In a dialog a select and its Add button do not sit side by side: the select takes the full width and a small Add sits under it.

Checkboxes

  • X3Disabled: opacity 0.5. Focus: the 2px accent ring.

Lists and rows

  • R1Rows 0.25rem apart, 0.5rem vertical padding, gap 1rem between the text and the actions.
  • R2Every even row gets a band of 3% --text, radius 0.75rem. Inside a card the band reaches out so the row text keeps the card's padding line. No hover highlight on rows.
  • R3Row text: title 600 --text; meta 0.875rem --secondary; extra detail lines 0.8rem --secondary. Split dense data over two or three short lines rather than one long one.
  • R4Long lists show 10 rows, then a centred small More button.
  • R5An empty list shows a centred --secondary note and keeps at least one row's height, so the card does not jump.
  • R6Group label: 0.75rem/700, 0.06em, uppercase, --secondary, 0.25rem above its rows.

Groups and fold arrows

  • W1A group title in a grouped list is a small raised box: the grey fill, hairline, radius 0.6rem, the label in --text caps, the arrow inside after the text.

  • AX1prefers-contrast: more: the glass surface turns solid; --separator, --edge and --card-edge become --text, so every edge is a visible outline.

Checklist for new work

  • Z1Find the existing class or token first; add a rule only when nothing covers it, on the shared structure (P10).
  • Z2Pick the color by role (C1). Accent only for act or progress (P2); text only --text or --secondary (P3); a status gets a word (P4).
  • Z3Can the user act on it? Raised (E2). Not? Flat (E3). A container? The card look.
  • Z4Give it every state: rest, hover (inside @media (hover: hover)), focus-visible, disabled (the opacity table), selected (the washes table).
  • Z5Check both modes, a phone width, 44px targets, and the change's Undo toast.
  • Z6Run the contrast test (text pairs, no accent text, no literal colors, every differing token registered and faded) and the accessibility scans.
  • Z7Update the project's design-system page and decision log in the same change.

Adopting this in a new project

  1. Copy the starter CSS: tokens, the two [data-theme] rules, the base recipes. Add the @property registrations and the fade rule if you want the mode fade.
  2. Pick the accent (AC1–AC6) and replace --tint, --tint-hover, --tint-subtle and --glow together.
  3. Write a contrast test before the first screen: it computes K1–K4 for every token pair in both modes, fails on color: with an accent or status token, fails on a literal color outside the token block, and checks every mode-dependent token is registered and in the fade list.
  4. Add the inline theme script (reads the saved choice, sets data-theme before paint) and an Auto / Light / Dark segmented control in Settings.
  5. Build one reference page fully, with every state; build every other page to match it.
  6. Start the project's own design-system page from this one: keep the rule IDs, replace the examples with the project's components, and log each new decision with its reason and the rejected options.
  7. Review every component in light and dark side by side before calling it done.
