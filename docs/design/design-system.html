How to use this page

  • U1Every rule has an ID (P1, B4, H2…): quote it in a request or a review ("this breaks B6").
  • U2Every example is drawn twice, Light on the left and Dark on the right (stacked on a phone), with the app's own token values, so what you see is what the app draws. Hover works on the examples with a mouse; states that need an action (hover, focus) are also shown frozen.
  • U3Code wins. If this page and app/globals.css ever differ, the CSS is right and this page is updated in the same change (golden rule 5). The decisions' full text, with the rejected options, is in docs/kb/decisions/general.md.
  • U4Older design files are kept in docs/design/ with names that start with OLD-. They are history: never build from them.

Principles

The owner opens the app all day (food, gym, tasks). The look should feel serious, motivating, energetic and orderly, like Apple's native apps, with one accent everywhere (D-020, D-022).

  • P1Change the look, not the structure. Aesthetic work never moves screens, adds features or changes layouts unless the owner asks for that change.
  • P2One accent: turquoise. It marks only what means "act" or "progress": the primary button, progress fills and rings, the active segment's dot, the focus ring, a checked checkbox, a selected chip. Never decoration (D-020, D-022).
  • P3Accent and status colors are never text. Text is --text or --secondary; a colored fill carries the dark --on-tint label. One exception: the Wishlist total's large "RON" (D-021, D-029).
  • P4A status is never color alone. A word always goes with it (a badge's text, a "Over" label) (D-022).
  • P5Raised means you can act on it. Buttons, fields, selects, checkboxes, chips, fold arrows, tabs: hairline edge + soft shadow. Tags, counts, info tiles stay flat. Containers (cards, sheets) keep the card look (D-031).
  • P6Neutral grey for everything that is not the primary action. Secondary, small, icon and toast buttons share --surface-secondary; selected states use a neutral wash or the subtle turquoise, never a solid accent (D-024, D-028).
  • P7Two modes, one token list. Dark and light follow the system, or the Auto / Light / Dark switch in Settings; every color token is written once with light-dark(light, dark) (D-020, D-024).
  • P8"Alive" without animation. Big bold numerals for key metrics, a clear weight hierarchy, glass cards on a turquoise glow. Nothing moves except the existing animations (Motion) (D-022).
  • P9One font: SF Mono (monospace), for the even rhythm and aligned numerals (D-023).
  • P10One style everywhere. Set a style once on the shared structure (tokens, base element rules, shared classes) and let children inherit; no per-page copies. Wishlist is the reference page (CLAUDE.md, the plan's "Where styles go").
  • P11No literal colors outside the token block. Everything else is a token or a color-mix() of tokens (enforced by tests/palette-contrast.test.ts).
  • P12Every change has an Undo toast, the theme switch included (CLAUDE.md).

Color tokens

All tokens live in one :root block at the top of app/globals.css, with color-scheme: light dark. [data-theme="light"] / [data-theme="dark"] on <html> force a mode (the Settings switch, saved per device under localStorage["lt-theme"], applied before first paint by an inline script). Every color token that differs between modes is also registered with @property … { syntax: "<color>" } so the mode change can fade (Motion).

  • C1Use a token by its role, not by its look: a field is --surface-secondary because it is a control, not because it is "the light grey".
  • C2Accent and status colors share about the same brightness in each mode: no pale colors in dark, no dull or brownish ones in light (D-020).
  • C3A new color is a new token with both values, registered with @property and added to the fade list; never a literal in a rule.

Contrast and color use

  • K1Text at least 4.5:1 in both modes: --text and --secondary on --surface-solid, --surface-modal, --surface-secondary, --background, on the background with the glow at its peak, and on the three -subtle fills over the card.
  • K2--on-tint (dark, the same in both modes) on --tint, --tint-hover, --success, --warning: at least 4.5:1. Never put --on-tint on --danger (4.2:1 in light).
  • K3Colored fills at least 3:1 on the card and the page. One exception: light --warning #cc8c0a (2.9:1 on the card), the owner's choice; the status word carries the meaning, and the test holds it to 2.5.
  • K4No colored fill on --surface-secondary (2.9:1 in light): a track is --separator or a -subtle fill.
  • K5No color: declaration takes --tint, --success, --warning or --danger (fills, borders, fill, stroke may). Links are --text, weight 600, not underlined (D-029). Error text is --text 0.875rem, never red.
  • K6The one exception to K5: .item-currency, the "RON" beside the Wishlist total, is --tint (large text, 3:1 as a fill), at the owner's request (D-029).

Page layout and glow

Spacing inside a card

  • S1Card padding --card-pad: 1.35rem (1.6rem ≥768px).
  • S2Title → content: 1rem visible. Block → block: 1rem. Groups: 1rem apart. A group label sits 0.25rem above its rows (D-030).
  • S3The last row's text sits one card padding from the bottom edge; a card's last line (e.g. the 7-day average on Steps) drops its bottom margin (D-033).
  • S4Rows carry 0.5rem padding top and bottom; a header right before a list keeps 0.5rem and the list 0.5rem (.section-head:has(+ …)). Gaps of 24–29px between groups come from band parity, not a different rule.
  • S5A card's sub line sits 0.5rem under its title (.card-sub, D-031). .section-head: wrap, gap 1rem 0.75rem, margin-bottom 1rem.
  • S6Forms: .form-stack gap 1rem; .form-actions buttons flex 1, gap 0.75rem; a header with two buttons gives them equal columns (.head-actions). In a dialog a list's text starts and ends at the body padding.

Buttons

  • B1Base button (primary): --tint fill, --on-tint label, 700, -0.01em, padding 0.65rem 1.25rem, min-height 2.75rem, radius 0.85rem, --card-edge border, --card-shadow, inline-flex, gap 0.5rem. Hover: --tint-hover.

  • B6Secondary .secondary: --text on --surface-secondary. Small .btn-sm: the same fill, min-height 2.25rem, padding 0.35rem 0.85rem, 0.875rem/600, radius 0.7rem, a 44px hit area from ::before (Add, More, Sign out, Edit, Start, Sort). Hover, focus and press

  • Y1Hover exists only under @media (hover: hover), so a phone never keeps a stuck hover.
  • Y2The hover steps: turquoise → --tint-hover; neutral fills (secondary, small, icon, toast Undo and close, modal close, category boxes, idle muscle chips, an unselected day card) → color-mix(--surface-secondary, --text 8%); danger → color-mix(--danger-subtle, --text 8%); fields and the sort select → 5%; idle tabs and segments → --highlight wash with --text; idle nav links → --surface-secondary with --text; the round close buttons also turn their icon to --text.
  • Y3Focus: buttons and checkboxes get a 2px --tint outline, offset 2px, on :focus-visible. Fields show no ring: their fill steps to 8% (one step past hover). The sort select shows the ring for the keyboard only (not after a pointer press, data-pointer).
  • Y4Rows have no hover highlight. Press has no effect (B11).

  • F3The select's chevron is two linear-gradient strokes in --secondary (no data-URI, so it follows the token); --chevron-end: 1rem, padding-right 2.6rem.

Checklist for new work

  • Z1Find the existing class or token first (this page, then app/globals.css); add a rule only when nothing covers it, on the shared structure (P10).
  • Z2Pick the color by role (C1). Accent only for act / progress / active (P2); text only --text / --secondary (P3); a status gets a word (P4).
  • Z3Can the user act on it? Raised (E2). Not? Flat (E3). A container? The card look.
  • Z4Give it every state: rest, hover (in @media (hover: hover)), focus-visible, disabled (the opacity table), selected (the highlights table).
  • Z5Check both modes, a phone width, 44px targets, and the change's Undo toast.
  • Z6Run npm run check (the contrast test: pairs, no accent text, no literal colors, every differing token registered and faded) and the @a11y e2e scans (npm run e2e).
  • Z7Update this page and the KB decision in the same change (golden rule 5).

Reuse in another project

  1. Copy the token block (Color tokens), with color-scheme: light dark, the two [data-theme] rules and, if you want the fade, the @property registrations and the [data-theme-fade] rule.
  2. Copy the recipes in this order: base (font, headings), surfaces and the raised recipe, buttons, fields, checkbox, segmented, badges, lists, modal and toast.
  3. Keep the rules, change only the accent: replace --tint, --tint-hover, --tint-subtle and --glow together, then re-check K1–K4 (a contrast test like tests/palette-contrast.test.ts is worth copying too).
  4. Keep the two-pane habit: review every component in light and dark side by side before calling it done.
