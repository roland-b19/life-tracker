Life Tracker on Azure

Azure course project · one-page plan: what the app is and where each Azure service will be used

The application

Life Tracker is a personal tracker that will run in the browser and as an installable app on the phone's Home Screen (a PWA). It will offer tasks (daily or one-off, with streaks and reminders), a wishlist, health tracking (weight, water, steps, food), a gym log (plans, workouts, sets, progress) and a shopping list. It will hold personal and health data, so security will drive the design: each user will see only their own data, and the database will not be reachable from the internet.

How it will fit together

compute (runs code)storage (keeps data)securitymonitoring

  1. The user will sign in with a Microsoft (Entra) account over HTTPS and open the web app.
  2. The web app will read and write that user's data in the database, and only that user's data.
  3. Every minute the enqueue job will look in the database for reminders that are due now.
  4. It will put one small message per reminder in the queue. The message will hold only ids, no text.
  5. Every minute the send job will take the messages from the queue and check again that the task belongs to that user.
  6. It will send a push notification to the user's phone.

Where each course requirement will be met

RequirementAzure service and its role
1. ComputeAzure Container Apps will run the web app and the three jobs (enqueue, send, and a one-off job that sets up the database tables).
2. Database or storageAzure PostgreSQL will store all application data. Azure Storage will hold the reminder queue. Container Registry will store the app images.
3. Secured appThe database, Key Vault, registry and queue will sit behind the private network, with public access switched off. Key Vault will hold every secret. Managed identities (accounts for the services, with only the rights they need) will replace passwords and keys. Traffic will be HTTPS only.
4. Authentication and authorizationMicrosoft Entra ID will handle sign-in. The app will give each record an owner and filter every request by the signed-in user. Tests will check that other users and anonymous visitors are refused.
5. Message queueAzure Storage Queue will pass reminders from the enqueue job to the send job (steps 3 to 6 above).
6. Real functionalityThe five modules (tasks, wishlist, health, gym, shopping) in one app that will run on Azure.
7. Scripted deploymentBicep (infrastructure as code) will describe every resource. Scripts will preview the change, ask for approval, deploy, and delete everything. No portal clicking.
8. Cloud backend and database, securedThe backend will run in Container Apps and reach the database only over the private network. The phone app (PWA) will be the client.
ObservabilityLog Analytics will collect logs from all services. Three alert rules (web errors, app restarts, queue backlog) will e-mail the owner through an action group. Four saved queries will show errors, reminder runs, queue activity and Key Vault access. A budget alert will watch the cost.
DeploymentFor each iteration: deploy with the script, work, present, then delete everything so the course credit lasts until January. An ephemeral run is expected to cost well under 1 USD (estimate).
