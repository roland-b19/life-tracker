# Gym page audit — 2026-11-16

Code review plus a browser run on a throwaway database. Nothing here is implemented yet; the user decides what to fix. IDs: G = code review, E = browser run.

## High
- **G-1 / E-3 / E-9 Deload is week-wide, not per session.** `saveDeloadWeeks` (`src/lib/gym.ts`) bulk-updates `isDeload` for every session in a week, so removing a deload week clears the flag of finished sessions the user marked. The "Deload session" toggle (`gym-client.tsx`) is never reset after a start and is not re-synced after editing deload weeks. Fix: `isDeload` is set only per session at creation, drop the bulk updates, reset the toggle after each start, initial state from the session.
- **G-2 / E-4 Load input defaults to 40 for every exercise.** `parseFloat(x) || 0` turns empty or invalid text into a 0 set. Bodyweight and plates sets log a stale 40. Fix: prefill from the last set or leave empty and disable Log; bodyweight defaults extra 0 and hides the load field.
- **G-3 / E-4 Progress mixes units.** `gym-progress.ts` sums `loadValue + extraKg`, so 7 plates + 5.5 kg shows as "8 × 12,5 plates"; averages mix load types and "kg" is always printed. Fix: compute per load type and show the unit.

## Medium
- **E-1 Undo after a reload scrambles History order.** `app/gym/page.tsx` maps the open session and its sets without `createdAt`, so `restoreWorkoutSession` falls back to now. Fix: include `createdAt` in the mapping.
- **E-2 / G-7 Finish or Log set on a session deleted elsewhere reports success.** The update hits 0 rows and is not checked; the screen stays in a ghost workout. `deleteSetAction` and `finishSessionAction` also return success when nothing matched. Fix: check affected rows, return an error, refresh.
- **G-4 / E-6 Client limits differ from server limits** (reps 1-200, load 0-1000, extra 0-300, notes 500). Over a limit the user gets a generic toast and the set is lost; `deleteSetAction` and `logSetAction` throw a raw ZodError. Fix: shared constants, inline errors, keep the values on failure, `safeParse` in the actions.
- **G-5 Two open workouts are possible; Finish without a duration leaves the session open; a second finish overwrites.** Fix: reuse or reject an open session in a transaction, partial unique index, compute the duration on the server, repeated finish is a no-op.
- **G-6 / E-10 The anomaly flag trusts the client's `minTargetReps`.** Fix: read it on the server from `workoutSplitDayExercises`.
- **G-7 Undo is incomplete.** A restored set loses flags and notes, `takeBack` does not restore `selectedDayId`, `reopenWorkoutSession` nulls the notes.
- **G-8 Session date is unbounded and comes from the browser.** Fix: bound it to today ±1 and use the server date.
- **G-9 / E-7 Duplicates under concurrency.** `ensureUserDefaultSplit` is 7 inserts without a transaction; custom exercise names and split-day exercises have no unique constraint (the default-name index in migration 0030 covers only defaults).
- **G-10 Custom exercises cannot be renamed or deleted in the UI.** `deleteCustomExercise` exists but is unused. Add rename and delete with Undo, or remove the dead function.
- **G-11 The muscle group "other" is invisible in the muscle explorer.**
- **E-5 The modal closes when a drag starting inside the card ends on the backdrop** (`app/components/modal.tsx`, the backdrop `onClick`). Typed input is lost. Fix: close only when pointer down and up were both on the backdrop. Affects every form in the app.
- **E-8 A DB outage sends the whole page to the error boundary** (the `router.refresh()` after a server action); with a hanging DB, Start stays disabled with no timeout.

## Low
- G-12 `logSetAction`/`deleteSetAction` do not revalidate. G-13 missing indexes (`exercises.userId`, `workoutSplitDayExercises.splitDayId`, `workoutSets (userId, exerciseId, createdAt)`). G-14 `restoreWorkoutSession` set id collision gives a generic PK error. G-15 the workout timer lives in localStorage.
- E-10 raw enum text in the UI ("TOO_HEAVY", "bodyweight"). E-11 progress chart X axis is by workout, not by date. E-12 the Deload checkbox has no own aria-label.

## Test gaps
No authorization trio (owner, other user, anonymous) found for `logSetAction`, `deleteSetAction`, `createSessionAction`, `saveDeloadWeeksAction`, `createCustomExerciseAction`. No tests for G-1, G-5, G-8, G-9, mixed load types, week-boundary progress or the client Undo flows.

## Verified working (browser)
Isolation between two users, anonymous redirect, per-session deload, comma/dot decimals, select-all, Enter/Esc, delete set + Undo and Cancel workout + Undo (same page lifetime), resume after reload, History, periods, muscle map chips, day reorder/edit, custom exercise add, 375px layout without overflow.

## Not covered
Real touch devices (iOS keyboard), Undo of Finish after a reload, arbitrary past/future session dates, screen-reader order, performance with a large history, the Three.js muscle model (WebGL was unavailable in the test pane).
