## Found live: the Azure schema had drifted (first deploy)

- After the Entra sign-in worked, the Gym page showed the error page, the data export failed and the Food page failed. The app log showed `relation "deload_weeks" does not exist` and `column r.is_estimated does not exist`.
- Cause: the migration job ran `scripts/db-init.cjs`, which created the tables from its own copy of the schema (about ten migrations behind), not from `drizzle/`.
- The missing Enable button on Tasks looked like part of this, but it had its own cause (next section).
- Fix: the image now carries `drizzle/` and the Drizzle migrator, and `db-init.cjs` only creates the database and the role, then applies the migrations. Tested in the built image against a throwaway Postgres: 32 migrations applied, 22 tables, a second run changes nothing, the app role can read `deload_weeks`. A contract test keeps hand-written `CREATE TABLE` out of the script.
- The broken deployment was deleted and redeployed from scratch with the fixed image (a clean database, no reset flag in the script).

## Found live: public/ was missing from the image (second deploy)

- On the redeployed environment (32 migrations applied, Gym and export working) the Enable button for task reminders did not appear and no notification arrived. `/sw.js` and `/manifest.json` answered 404.
- Cause: the standalone Next.js output has no `public/` and the Dockerfile never copied it, so the service worker never registered, `navigator.serviceWorker.ready` never resolved and the button stayed hidden. The icons and the 3D muscle models were missing too.
- Fix: the Dockerfile copies `/app/public`; a contract test checks it. Applied in place (no teardown): the registry was opened for the owner's IP only for the push, closed again (public access Disabled), and the web app updated to the new image digest. `/sw.js`, the manifest and the icons then answered 200 and the button appeared.

## Found live: reminders arrived a minute late (in place fix)

- The `enqueue` and `send` jobs started at the same instant, so `send` found an empty queue and the push waited for the next minute. Fix: the `enqueue` job runs `send.mjs` right after `enqueue.mjs` in one execution (`replicaTimeout` 100); applied in place to the job, no image change. The executions after the update ended `Succeeded` in about 27 s.
