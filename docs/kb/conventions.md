# Conventions

## Working together
- The owner writes Romanian: chat replies are in Romanian. Code, comments, commit messages and PRs are in English.
- Ask before changing the stack, adding a dependency, creating any Azure resource or anything that costs money. Do nothing the owner did not ask for.
- Never run a command against the live database; never ask for a connection string, token or key in chat.
- **When the user is away:** after the user says they are away or asleep, don't wait, ask questions or ask permission until they are back. At each choice take the option you would recommend, keep going, and list the choices made in the PR body and the KB log. The user's away message can allow what normally needs their word, such as merging; the safety limits still hold.

## One way to do each job
- **Planning a feature:** the plan-feature skill, before any building.
- **Finding code:** plain search (Grep, Glob, reads) for ideas and areas, starting from the KB architecture page. Where a language server plugin is installed, use the LSP tool only when an exact location is needed: a definition, every caller or reference before changing or removing something, or the exact line to edit; never to browse. Its automatic error reports stay on. No stored code indexes.
- **Finding KB facts:** INDEX first; when it names no page, the KB search (maintain-kb SKILL.md, Search), then read the sections it points to. Grep only to list every occurrence of an exact string, such as a decision's usages.
- **Reads in a page and the session guard (D-011):** a `page.tsx` starts with `const user = await requirePageUser("/<route>")` from `src/server/auth.ts` (redirects to `/signin?next=/<route>`, so signing in returns there; gives `user.id` and `user.name`), before any data read. `RequireSession` stays the layout of every signed-in route, rendered with the same `path`, and the page still calls the helper. A page or layout without its path is deprecated (status, tracked migrations). `optionalPageUser()` is only for pages anyone may see (the 404 page), never a guard. Never call `getServerSession` or `redirect("/signin")` in `app/`; `tests/pages-auth.test.ts` covers every new page and layout by itself.
- **Writes from the UI:** a `"use server"` action in `src/actions/<feature>.ts` that does `return respond(async () => { const userId = await requireUser(); ... })` from `src/lib/validations/result.ts`, `requireUser()` the first line inside it, so a signed-out caller gets `{ success: false, error: SIGNED_OUT }` ("You're signed out. Sign in again.") instead of a 500 (a flagged action calls `assertClaudeEnabled()` / `assertPushEnabled()` before `respond`); calling `requireUser()` before `respond` is deprecated (status, tracked migrations). The body parses with zod `.parse()` (schemas in `src/lib/validations/`, ids with `uuid` from `common.ts`) and calls `src/lib/<feature>.ts`. Every new action ships an authorization test: owner allowed, other user denied, anonymous denied.
- **Action result (D-010):** `{ success: true, ...data }` or `{ success: false, error }`; a failed `.parse()` and `throw new Refusal("message")` (expected refusals: not found, a rule of the page, a duplicate) become the failure. Never throw for something the user should read (Next hides it in production), never return `null` for "not found", never `safeParse` or a hand-written check in an action. `respond()` also turns an `UnauthorizedError` from `requireUser()` inside it into the SIGNED_OUT failure; only flag guards and real faults throw. Zod issues reach the page as people's messages (`z.config` in `result.ts`: "Required", "Must be a number", "Too long (max N)") unless the schema gives its own. Clients check `.success`, never "did it throw"; tests narrow with `succeeded()` from `tests/succeeded.ts` and assert refusals as `{ success: false, error }`.
- **Names:** a function that adds a row is `add<Thing>` in every layer (`src/lib`, the `...Action`, the zod schema `add<Thing>Schema` and its `Add<Thing>Input` type): never `create...`. Server actions never call `revalidatePath` (the client keeps its own state; `app/providers.tsx` refreshes the router cache once writes stop); `tests/query-count.test.ts` fails on it. The page route is `/health` to match the Health label; the liveness route is `/api/health` (D-013).
- **Imports:** `@/` is `src/` (tsconfig `paths` and the Vitest alias). A module under `src/` imported from another folder is always `@/...`, never `../`. A module in the same folder is `./x`. Root `app/` and `worker/` are outside the alias, so `app/**` reaching `app/components/` and tests loading `../app/...` or `../worker/...` use `../`; that is the only place `../` is allowed. Not enforced by lint.
- **Test auth and users:** `tests/auth.ts` holds the signed-in user and the test users. A test file mocks the auth module with `vi.mock("@/server/auth", async () => (await import("./auth")).authModule);` (the factory runs lazily, so the hoisting is no problem) and imports `authState` (`authState.id = userA` signs in, `""` is anonymous; `authState.UnauthorizedError` is the error to expect) and `seedUser(subject?)` (inserts a user, returns its id) from `./auth`. Never copy either into a test file. A test that needs a different mock (the always-anonymous mocks, `next-auth` in `query-count.test.ts`) keeps its own.
- **Undo:** every change has an Undo toast; the delete restores the row under its old id. The toast's `onUndo` is `undoWith(showToast, write, failed?)` from `app/components/toast.tsx`, never a hand-rolled block: `write` puts the screen back first, then writes, and reverts the screen itself if the write fails. It returns the action's answer (`{success}`, a boolean or nothing) or throws; a refused restore is `{success: false, error}`, so `back.success` decides whether the screen keeps the row. `undoWith` shows the "Failed to undo" warning (or `failed`, a string or a function of the answer) when the answer is falsy, `{success: false}` or a throw, and nothing when it is `true` or `{success: true}`; return `true` when there is nothing left to write and the screen is already right.
- **Double taps (D-043):** a button that writes acts once per tap burst through the one shared guard, `useOnce()` in `app/components/once.ts` (one write at a time per target, a row's key or the form, so a tap on another row's button still writes; then the tapped spot swallows clicks for 500 ms, never the toast's); `FormModal` uses it for Save. Never a component's own lock or debounce.
- **Adds made on the device (D-040):** an add sends `id: crypto.randomUUID()` (`newId` in `src/lib/validations/common.ts`); the insert uses it with `on conflict do nothing` and answers success, so a repeat after a lost answer adds nothing. Categories are keyed by name and take no id (D-045).
- **Server data in a client list (D-034):** a client component keeps what the page sent in `useServerState(initial, { editing, onDeleted })` from `app/components/server-state.ts`, never a plain `useState(initial)`: a refresh replaces it, and an open edit form on a row that is gone closes with "This item was deleted.".
- **Refreshes (D-034):** only `app/providers.tsx` refreshes the router: 600 ms after the last write, in the other tabs of the browser through a `BroadcastChannel`, on focus or becoming visible (not within 2 s of the last refresh or load), every 60 s while visible, and at 00:00 `Europe/Bucharest` (`watchDay` in `app/components/day-watch.ts`); a refresh that comes due while offline runs once the device is back online (the window's `online` event, or the next trigger) and `/api/health` has answered (`cache: "no-store"`; the service worker never answers it), because Next turns a refresh that fails into a full page load, which would drop an open form. The browser keeps a copy of each page seen (`staleTimes` in `next.config.ts`: 120 s for visited pages, 300 s for the tab bar's prefetches), and only a refresh drops it, so a tap on a link of the app while a write is unanswered, or while a refresh is due (after this tab's write or another tab's), waits: the refresh runs at once after the answer (not 600 ms later) and the tap goes through as soon as the refresh request has started, at most 10 s after the tap (`HOLD`), so a write that never answers cannot keep the app on one page. A tap with a modifier, or on a link that leaves the app, goes through at once. A write without an answer says "You're offline. Nothing was saved." or "Couldn't confirm the change. Reloaded.".
- **Signals inside one tab (D-044):** a React context with a hook in `app/providers.tsx` (as `ToastContext` and `usePageNotOpened`), never a `window` event.
- **View controls per device (D-041):** `useDeviceState(key, fallback)` from `app/components/device-state.ts` (`localStorage`), never a hand-written storage read.
- **Number fields (D-037):** `formatNumber`, `parseNumberInput` and `NOT_A_NUMBER` from `src/lib/number-format.ts` (shown and typed as `1.500,5`); `src/lib/decimal-input.ts` is deprecated (status, tracked migrations).
- **Undo keys:** a toast with Undo names the rows it touches, `touches: ["<table>:<row id>"]` (`<table>:*` for a whole list); a newer toast touching one of them takes the older one's Undo away. Keys use row ids, never names (D-045). Pass `saved` (the write's promise) so a failed write removes its success toast.
- **Form error state:** `const [errorMsg, setErrorMsg] = useState("")` (D-009). `FormModal` keeps its `error` prop; pass `error={errorMsg}`.
- **UI:** the Wishlist page (`app/wishlist/`, `app/globals.css`, `app/components/`) is the reference. Dark and light modes (the system's, or the Appearance switch in Settings, D-024), no animations except the existing ones (the dark/light fade, D-025, is one). Every visual rule, with an ID and a light and dark example, is in `docs/design/design-system.html`: check new UI against it and update it in the same change as `app/globals.css`. Files in `docs/design/` named `OLD-…` are history, never a source. `docs/design/design-rules-general.html` is a project-agnostic snapshot for new projects, not kept in sync.
- **UI spacing (D-030):** inside a card the visible gap from the title to the content, and between blocks, is 1rem; a group label sits 0.25rem above its rows and groups sit 1rem apart; the last row's text sits one card padding (`--card-pad`) from the bottom edge; in a dialog a list's text starts and ends at the body's padding, the gap every dialog keeps under its title. List rows carry 0.5rem padding, so a header right before a list keeps 0.5rem and the list 0.5rem (`.section-head:has(+ …)` in `globals.css`). A big numeral or a one-line note between blocks is trimmed with `text-box: trim-both cap alphabetic` so its 1rem margins are the visible gaps. Gaps of about 24–29px between groups come from row band parity (a last row without a band), not from a different rule. Everything actionable (buttons, fields, selects, checkboxes, chips, fold arrows, collapsible titles, in forms, dialogs and sign-in too) takes `--card-edge` and `--card-shadow`, as do cards, tabs and segmented controls; tags, counts and other things you cannot act on stay flat (D-031). The turquoise buttons' edge is `--tint` mixed with `--text`, since the hairline vanishes on turquoise; disabled, Save, Log set and Send look like the secondary buttons (their fill and hairline), with the label faded to `--text` at 45% like any disabled button (D-033). A row's detail lines under its title and tag (a muscle map exercise's days, a custom exercise's equipment) use `.entry-detail` (D-032).
- **Long lists:** show 10 rows, then a More button. Two forms exist, pending the owner's choice (status, open questions): `useMore` (`app/components/lists.tsx`, More adds 10 inline; Gym history) and `useMoreDialog` (More opens a `Modal` with the full list; Health meals, D-029). A group of rows under a category title uses `GroupToggle`, which draws the title as a box (D-029).
- **Dependency versions:** caret ranges (`^x.y.z`) in `package.json` and `worker/package.json`; the lockfile pins what is installed. No new exact pin. The one deliberate exception is root `three` and `@types/three` (kept exact, `0.187.0`): 0.x libraries ship breaking changes in minor releases and a caret on 0.x does not allow a minor bump anyway, so the owner moves them by hand. Chosen by the owner on 2026-11-18.
- **Migrations:** additive Drizzle migrations with explicit GRANTs; the owner runs them on the live database before the dependent code merges.
- **Checks:** the verify skill has run at the change's test tier, the fast checks pass, and review-change has run; its PR body lists every finding as fixed or with a reason.
  - **Fast checks** (the one check command): `npm run check` (lint, typecheck, tests, KB check). Tests need Postgres, see Gotchas.

## Gotchas
- **Next.js 16:** has breaking changes against older versions. Read the guide in `node_modules/next/dist/docs/` before changing framework-level code.
- **Postgres for tests:** `npm test` needs Postgres. Locally `docker compose up` provides it; without Docker or Postgres the DB-backed tests cannot run, and CI is the proof. Each worktree (`.claude/worktrees/<name>`) tests against its own database `life_tracker_test_<name>`, and the main folder against `life_tracker_test` (D-018), so parallel sessions never truncate each other's data. `tests/global-setup.ts` (Vitest and Playwright, not in CI) creates the database if it is missing and migrates it, from `tests/local-db.ts`. A database outlives its worktree: drop it when the worktree is removed (`DROP DATABASE life_tracker_test_<name>` as `postgres`). To use another database, run with `CI=1` and `DATABASE_URL` and `DATABASE_URL_MIGRATE` both set to it.
- **Local credentials:** the Docker passwords and `DATABASE_URL_TEST` are written only in `.env.example` (D-006). `docker compose` and `seed:dev` read your `.env`, a copy of it (`cp .env.example .env`); `tests/local-db.ts` reads `.env.example` itself, so keep `.env` in step with it. A worktree's own Postgres starts with an empty dev database, so `npm run dev` there fails to sign in (`Failed to sign in`) until `node --env-file=.env node_modules/drizzle-kit/bin.cjs migrate` and `npm run seed:dev` have run (`npm run seed:dev -- owner test` fills each named dev user, default `demo`, with sample data for every page; open Gym once first so the split exists; it never overwrites); the test databases are migrated by the specs themselves. In CI the job's env is the only source and `tests/setup.ts` has no defaults. Never write a password in code, a script or a doc.
- **Time zone:** compute "today", the weekday and the clock time with `src/lib/format-date.ts` (`APP_TZ`: `toISODate`, `weekday`, `appTime`), on the server and in client components alike. Never `new Date()` day math or a device-local API (`getDay`, `getHours`, `toTimeString`, `toLocaleDateString` without `timeZone`, and the like): the server runs in UTC and a device can be anywhere. `tests/format-date.test.ts` scans `app/` and `src/` and fails on them. `public/sw.js` and `scripts/seed-dev.cjs` are outside the scan.
- **New table:** add a GRANT for `life_tracker_app` in the migration, or the app cannot use it.
- **Postgres version:** pinned in four places that must match: `.github/workflows/ci.yml`, `.github/workflows/backup.yml`, `docker-compose.yml`, `scripts/backup-now.sh`.
- **Service worker cache:** the cache name in `app/components/page-cache.ts` must match `PAGES` in `public/sw.js`; bump `CACHE` in `public/sw.js` to refresh the muscle model.
- **Manual scripts:** `scripts/backup-now.sh` (plaintext dump of the live database into `.local/backups/`) and `scripts/import-personal.cjs` (wishlist and tasks from `.local/personal-data.json`) have no npm script or caller on purpose (D-008). Only the owner runs them, with `DATABASE_URL_MIGRATE` typed into a hidden prompt; never run them yourself. A change to `wishlist_items`, `todos` or `item_categories` must also update the importer.
- **Backup workflow:** `.github/workflows/backup.yml` must not be weakened; the private `age` key stays with the owner.
- **Health data:** never sent to an AI provider.
- **iOS 26 bottom bar:** Safari draws nothing fixed under its bottom bar and fills that strip with the plain page color, so a fixed layer near the bottom edge (the glow) looks cut off; on a screen that never scrolls, make it `position: absolute` (D-032).
- **e2e server:** the server also gets `NEXT_PUBLIC_CLAUDE_ENABLED=true` and a throwaway `CLAUDE_TOKEN_KEY` (made from a fixed string in the config, not a secret), because the Claude card on `/settings` renders only with the flag (D-017); the flag also shows the Assistant tab on `/health` in every spec, and no spec opens that tab (it needs the `claude` CLI). `AUTH_DEV` throws under a production build, so `npm run e2e` starts `next dev` on port 3100, or `E2E_PORT` when set so parallel worktrees each run their own server (not `next start`) with `AUTH_DEV=true` and the local test database; the config takes `DATABASE_URL` from `tests/setup.ts` and refuses a non-local host (`CI=1` with a remote `DATABASE_URL` could otherwise reach a real database). It fails at start with Next's own message while another `next dev` runs in the same folder (stop `npm run dev` first). `next dev` also re-creates an `AGENTS.md`; it is in `.gitignore`, never commit it. `.dockerignore` lists `playwright.config.ts` because it imports `tests/setup.ts` (also ignored) and the image's `next build` typechecks every `**/*.ts` it can see; keep both ignored together. Vitest excludes `tests/e2e/**`; lint ignores `test-results/` and `playwright-report/`.
- **e2e cleanup and shared database:** the app role cannot delete users, so the `signedInPage` fixture deletes its user with `DATABASE_URL_MIGRATE` (the owner role, as the Vitest tests do); the config refuses a non-local host for both URLs. `npm run e2e` and `npm test` in one folder share its test database, and several Vitest files `TRUNCATE ... users CASCADE`: a Vitest run in the same folder during `npm run e2e` deletes the spec's user, and the add fails with a foreign-key error (`Failed to save item`). The Stop hook's `npm run check` is such a run: an agent that starts `npm run e2e` in the background and ends its turn breaks a random signed-in spec, so it waits for the run in the same turn. `npm run e2e` cannot start while `npm run dev` runs in the same checkout (Next allows one dev server per folder); to keep the owner's dev server up, commit and run it from a temporary `git worktree add --detach .claude/worktrees/<name> HEAD` beside it (`.env` copied, `node_modules` cloned with `cp -c -R`, not symlinked: Turbopack rejects that), then remove it and drop its `life_tracker_test_<name>` database. Run them one after the other; to run both at once, point the e2e run at its own local database (`CI=1` with both `DATABASE_URL` and `DATABASE_URL_MIGRATE` set to it). Another worktree's run no longer interferes (D-018).
- **e2e sign-in:** sign in through `/api/auth/csrf` and `/api/auth/callback/credentials` (`signIn` in `tests/e2e/helpers.ts`), not the `/signin` form. It is faster, and a spec about the form itself signs in through it (`tests/e2e/navigation.spec.ts`). On that page the first `/api/auth/session` calls (two under React StrictMode in dev) can each set a different CSRF cookie, so a token read in between is refused: NextAuth answers 200 with `csrf=true` in its url and no session. The form therefore keeps Continue, the GitHub button and the name field unusable until its session check has answered (`useSession().status`) or 5 s have passed without an answer (`SESSION_CHECK_WAIT_MS`), and tries a refused sign-in once more before showing "Failed to sign in"; a spec waits for Continue to be enabled (Playwright's `click` does), never with `networkidle` or a time.
- **Zod messages:** `z.config({ customError })` in `src/lib/validations/result.ts` is global and gives the people's messages only where a schema has none of its own; a schema's own `message` wins.
- **React error #441 in a 500 page's console:** expected. Next's `onCaughtError` logs every error an `error.tsx` boundary catches, in production with the message left out; its digest matches the page's Reference. Our `error.tsx` logs nothing.
- **Production session cookie:** `__Host-next-auth.session-token` (`src/auth.ts`); Playwright's `addCookies` refuses a `__Host-` cookie on http, so a spec against `next dev` uses the dev name.
- **Scroll anchoring in specs:** Chromium keeps a list in place when rows above it change; iPhone Safari has no anchoring. `.list-box` sets `overflow-anchor: none`, and a spec that checks a slide turns it off (`slideLikeSafari()` in `tests/e2e/categories.spec.ts`).
- **Ending a tap burst in a spec:** `page.keyboard.press("Shift")` ends `useOnce`'s burst (a key press ends it), so a setup click right before the tested tap is not swallowed.
- **Agent worktrees:** an agent run with `isolation: worktree` may branch from `main`, not the feature branch; its brief starts with `git merge --ff-only <branch>` (or `git reset --hard <branch>` in a fresh worktree) and checks the commit.
- **`.env` in worktrees:** the main folder's `.env` may point at the live database, so nothing copies it into a worktree (D-045; `.worktreeinclude` was removed, and a workflow update must not bring it back). A worktree that needs one copies `.env.example`.
- **Other worktrees:** `.claude/worktrees/**` carry their own test copies, so Vitest excludes `.claude/worktrees/**`; lint, typecheck and the Docker context exclude all of `.claude/`.
- **Language server:** the `typescript-lsp` plugin needs the global npm packages `typescript-language-server` and `typescript` (`npm install -g --ignore-scripts typescript-language-server typescript`). Installed on the owner's Mac on 2026-11-18.
