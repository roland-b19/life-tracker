# Plan: audit fixes

## Goal
A functional audit of every page (2026-11-20) found bugs, unclear rules and rough edges. The owner went through each finding and chose what to fix, and added three asks: open copies of the app stay in sync, an open app moves to the new day at midnight, and an edge swipe never goes back or forward. This plan fixes all of it, for the owner, the app's one user.

The findings' IDs (GYMA-01, X-STALE, ...) come from the owner's private audit report; each step below says what to build, so the report is not needed to build. Security-relevant detail stays in that report.

## Scope
- In: the fixes listed in the steps; the KB rules they change (D-034 to D-042); tests for each.
- Out: the owner's "Later" list on the status page (a Gym rework and new charts beyond D-038, toasts redesign, units of measure for Gym, animations); weekly tasks or any future-day planning; a realtime service or websockets; a unique index on workouts per day; dropping the recipes tables (a destructive migration, see Cleanup); new animations; findings the owner chose to skip (GYMA-13, GYMA-14, GYMC-08, GYMC-12, HTODAY-16, MORE-09, WISH-10) or found done (GYMC-13).

## Done criteria
- [ ] A save in one tab shows in a second tab of the same browser within 2 s, and in another browser within 60 s or on focus — checked by `tests/e2e/app-shell.spec.ts` (two pages, one context; a second context with focus).
- [ ] When the browser clock passes 00:00 `Europe/Bucharest`, an open page refreshes once by itself (no reload, no click), and the server's day logic gives the new day for a time after midnight while a workout started before midnight keeps its start day — checked by `tests/e2e/app-shell.spec.ts` (Playwright `page.clock`, asserting the refresh request), `tests/day-watch.test.ts` and `tests/gym.test.ts` (`vi.setSystemTime`). The server gets no clock override.
- [ ] Moving through the tab bar and the More menu leaves `history.length` unchanged, and a `touchstart` within 20px of either edge is cancelled — checked by `tests/e2e/app-shell.spec.ts`; the owner tries an edge swipe on the iPhone app.
- [ ] Every number reads `1.500,5`, typing `1500.5` or `1500,5` gives `1.500,5`, and a letter shows an error and stays in the field — checked by `tests/number-format.test.ts` and the area specs.
- [ ] Every finding named in a step has a unit test or an e2e assertion for its fixed behavior in that step's `tests:` — checked by each part's PR proof table, one row per finding ID.
- [ ] Each new or changed action refuses another user and a signed-out caller with `{ success: false, error }`, never a 500 — checked by the area test files and `tests/actions-anonymous.test.ts`; after part E, no action calls `requireUser()` outside `respond` (a `grep` in step 21).
- [ ] Signing out on one device leaves another device signed in, and a request with the signed-out token is refused — checked by `tests/auth-guard.test.ts`.
- [ ] Query budgets hold: `/gym` 14, `/health` 13, `/todos` 12, `/wishlist` 4, `loadTodosViewAction` 13 — checked by `tests/query-count.test.ts`.
- [ ] `npm run check` and `npm run e2e` pass; CI is green on every part's PR.
- [ ] Every build agent's work is checked, as soon as that agent finishes, by a fresh verify agent (no build context) that walks a checklist for that agent's steps in the browser on local test users and finds no open item — checked by its report, read by the owner. This session writes each checklist from the steps and the private report (what to open, type and see, and what to check in the test database) and keeps it in the session's notes folder outside the repo, since it quotes the report.

## Decisions
- D-034: open copies stay in sync; the day rolls over at midnight
- D-035: no swipe back or forward; tabs replace history
- D-036: data entered for today only; tasks are one-off or daily
- D-037: one number format, 1.500,5
- D-038: Gym progress rules (deload weeks, bodyweight charts, plates in kg, outlier check)
- D-039: Gym workout rules (one per day, server timer, empty workout removed)
- D-040: writes safe to repeat and honest about their outcome
- D-041: sign-out per device; controls remembered per device
- D-042: Shopping units merge, convert and keep only the last clear

Calls made while planning (the owner approves them with the plan): the workout timer moves to the server (D-039); "1 plate = X kg" sits on the Progress card (D-038); per-device sign-out uses a session row (D-041); set notes keep their 255-character column and get their own 255 limit; device-made ids cover every add action in the app (all of them are in the areas this plan touches); a feature flag's "disabled" check stays first and still throws, so `tests/features.test.ts` is unchanged; the theme stays a per-device setting and reaches other tabs of the same browser only; the midnight check is tested in the browser and with `vi.setSystemTime`, not with a server clock override.
