## Scope

- **In:**
  - **Database schema & tokens (Drizzle ORM):**
    - `api_tokens`: `id`, `userId`, `name`, `tokenHash` (SHA-256), `scope` ('food'), `lastUsedAt`, `expiresAt`, `createdAt`.
    - Migration with least-privilege grants to `life_tracker_app`.
    - `scripts/db-init.cjs` updated for cloud bootstrap parity.
  - **Security & AI Data Line Quarantine:**
    - Dedicated personal bearer tokens per user with narrow `food` scope.
    - Global kill switch (`AI_CONNECTOR_ENABLED=true/false`).
    - **Strict quarantine:** Only food tools are registered. Body weight, steps, gym splits, expenses, tasks, and business data DO NOT exist on this endpoint and can never be queried or manipulated by AI.
    - AI-logged meals are explicitly flagged as `isEstimated: true` in the food log and can be manually edited by the user.
    - Input bounds with Zod (calories 0–10000, macros 0–1000g, prompt injection text sanitization).
  - **Dual-Protocol Endpoints:**
    - **Endpoint 1: `/api/mcp` (Standard Model Context Protocol):**
      - JSON-RPC 2.0 handler over HTTP/SSE.
      - Implements `initialize`, `tools/list`, `tools/call`.
      - Compatible with Claude Desktop, Claude Custom Connectors, and MCP clients.
    - **Endpoint 2: `/api/ai/food` (Gemini Function Calling & OpenAPI):**
      - `GET /api/ai/food/tools`: returns Google Tool Declarations (function declarations JSON Schema).
      - `POST /api/ai/food/call`: executes a tool call for Gemini agents/scripts.
  - **Food Tools Suite:**
    - `log_meal`: `{ mealType, name, calories, protein, carbs, fat, date }`
    - `get_daily_food_summary`: `{ date }`
    - `get_recipes`: `{}`
    - `add_shopping_item`: `{ name, amount, unit, category }`
  - **User Interface (`/food`):**
    - "AI Assistant Connector" modal or card on `/food`.
    - Generate personal food token with single-click copy.
    - Pre-formatted configuration snippet for `claude_desktop_config.json` and Gemini integration.
  - **Vitest Test Suite (`tests/food-ai.test.ts`):**
    - Token generation, hashing, and authentication guards.
    - Rejection of unauthenticated or tampered tokens.
    - MCP `tools/list` returns only food tools.
    - Execution of `log_meal` via MCP and Gemini endpoints.
    - Strict multi-tenant isolation (User A token cannot view/edit User B's meals).
- **Out (deferred to later iterations):**
  - Entra External ID OAuth 2.0 dynamic authorization server (local token auth is sufficient and portable; Entra client can be bound in cloud finish).
  - Voice / audio streaming.

---

## Decisions Made

1. **Dual-protocol support:** Exposes standard MCP for Claude and OpenAPI/Function Calling for Gemini over a shared backend DAL.
2. **Personal Food Tokens:** Scoped, SHA-256 hashed bearer tokens generated by the owner with zero-friction copy/paste.
3. **Quarantine compliance:** Zero access to weight, steps, finance, gym, or tasks per `AGENTS.md`.
4. **Local-first execution:** Fully tested on local PostgreSQL Docker without Azure costs.
